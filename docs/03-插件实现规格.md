# 03 · 插件实现规格

> 本文件的每一条契约都来自**真实插件源码**（`dsh-workspace@0.1.0`、`dsh-find-plugins@0.2.10`、`dsh-mobile-bridge@0.3.5`）与 DSH 运行时的 **Inspect Provider 实时输出**，不是推测。
> 如果你要动手实现社区插件，这个文件是唯一需要的技术参考。

---

## 1. DSH 插件 = 一个 npm 包 + 两个半边

DSH 插件不是特殊格式，就是一个普通 npm 包，通过 `package.json` 里的 `dsh` 字段声明自己：

```json
{
  "name": "dsh-plugin-community",
  "version": "0.1.0",
  "type": "module",
  "main": "lib/index.js",
  "exports": {
    ".":                    "./lib/index.js",
    "./client":             "./lib/client.js",
    "./cordis.patch.yml":   "./cordis.patch.yml",
    "./package.json":       "./package.json"
  },
  "files": ["lib", "cordis.patch.yml", "README.md"],
  "dsh": {
    "bundle": { "patch": "./cordis.patch.yml" },
    "client": {
      "inject": [
        "@deepseek-ai/dsh-client-runtime",
        "@deepseek-ai/dsh-client-ui-sidebar"
      ],
      "platform": "web"
    }
  }
}
```

### 关键点（每一条都有实测依据）

| 项 | 说明 |
|---|---|
| `type: "module"` | ESM。三个参考插件全是 ESM |
| `exports."."` | host 半边入口 |
| `exports["./client"]` | **client 半边入口**，缺失则没有界面 |
| `exports["./cordis.patch.yml"]` | 必须暴露，否则 bundle 安装时找不到 patch |
| `dsh.bundle.patch` | 告诉 DSH 用哪个 patch 文件组装本插件 |
| `dsh.client.platform` | `"web"` |
| `dsh.client.inject` | 声明 client 半边依赖哪些前端包 |
| `files` | **必须包含 `lib/**/*.js` 与 `cordis.patch.yml`**，否则 npm 发布后是空包 |
| `peerDependencies` | DSH 核心包作为 peer，不要作为 dependency 打包进去 |

> ⚠️ 实测教训：一个已装的包 `dsh-webui` 打着「DSH 插件管理器」的名号，但它的 `package.json` **完全没有 `dsh` 字段**，`main` 指向一个普通 React 组件库。它根本不是 DSH 插件。**判断一个包是不是 DSH 插件，只看有没有 `dsh.bundle`，不要看名字。**

## 2. host 半边规格

### 2.1 必需导出

```js
import z from '@deepseek-ai/schemastery'          // 配置 schema
import { defineTool } from '@deepseek-ai/dsh-tools' // Agent 工具

export const name   = 'dsh-plugin-community'      // 插件名，必须与包名一致
export const inject = ['credentials', 'webServer', 'storage', 'tools']
export const Config = z.object({ /* ... */ })      // 可选：配置校验与默认值
export function apply(ctx, config = {}) { /* ... */ }
```

**全部四个都要用 `export const/function` 具名导出，不能 `export default`。**

### 2.2 `inject` —— 依赖声明

数组，元素是**服务名**。只有声明了才能通过 `ctx.<服务名>` 拿到。实测两个插件：

| 插件 | inject |
|---|---|
| `dsh-workspace` | `['credentials', 'sessionPersistence', 'webServer']` |
| `dsh-find-plugins` | `['tools']` |
| `dsh-workspace`（client 半边） | `['slots', 'sessions']` |

**社区插件建议的 inject：**

| 半边 | inject | 用途 |
|---|---|---|
| host | `['credentials', 'webServer', 'storage', 'tools']` | 凭据、HTTP 路由、缓存、Agent 工具 |
| host（可选） | `+ 'web'` | 如果要把社区数据接入 DSH 的搜索/抓取链 |
| host（可选） | `+ 'authorization'` | 如果要用 DSH 自己的授权流程 UI（Device Flow 也可不用） |
| client | `['slots', 'sessions']` | 槽位注入、会话上下文 |

### 2.3 `Config` —— 配置 schema

用 `@deepseek-ai/schemastery` 的 `z`。实测样例（`dsh-workspace`）：

```js
export const Config = z.object({
    baseUrl: z.string().default('https://api.deepseek.com'),
    timezoneOffsetMinutes: z.number().step(1).min(-720).max(840).default(480),
    peakWindows: z.array(z.array(z.number().step(1).min(0).max(1_440))).default([[540, 720], [840, 1_080]]),
    allowRemote: z.boolean().default(false),
});
```

社区插件建议 schema：

```js
export const Config = z.object({
    githubClientId: z.string().default(''),        // Device Flow 的 client_id（公开值）
    owner:          z.string().default(''),        // Discussions 所在的 owner
    repo:           z.string().default(''),        // Discussions 所在的 repo
    sources:        z.array(z.string()).default(['awesome-dsh-plugin', 'dsh-plugin-radar']),
    cacheTtlMinutes:z.number().step(1).min(1).max(1440).default(60),
    allowRemote:    z.boolean().default(false),    // 独立页面是否允许非本机访问
});
```

### 2.4 `apply(ctx, config)` 与 `ctx.effect`

`ctx.effect(fn, label?)` 注册一个可被自动回收的副作用——**这是唯一正确的注册方式**，插件卸载时 DSH 会自动调用返回的清理函数。

host 侧实测（`dsh-workspace/lib/index.js:213-236`、`:246`）：

```js
const register = (path, read) => {
    ctx.effect(() => webServer.register({
        kind: 'exact', path,
        async handler(req, res) {
            const requestId = typeof req.headers['x-request-id'] === 'string' && req.headers['x-request-id'].length > 0
                ? req.headers['x-request-id'] : randomUUID();
            if (req.method !== 'GET') {
                res.setHeader('Allow', 'GET');
                sendJson(res, 405, { status: 405, reason: 'METHOD_NOT_ALLOWED', message: '仅支持 GET 请求', fields: [], requestId }, requestId);
                return;
            }
            if (config.allowRemote !== true && !isLoopback(req)) {
                sendJson(res, 403, { status: 403, reason: 'FORBIDDEN', message: '项目预览默认仅允许本机读取', fields: [], requestId }, requestId);
                return;
            }
            try {
                const url = new URL(req.url ?? '/', 'http://localhost');
                sendJson(res, 200, await read(await getBrowser(await resolveProjectRoot(url)), url), requestId);
            } catch (error) {
                ctx.logger.warn(error);
                sendJson(res, 400, { status: 400, reason: 'PROJECT_PREVIEW_FAILED', message: error instanceof Error ? error.message : '项目预览失败', fields: [], requestId }, requestId);
            }
        },
    }));
};

register('/api/v1/dsh-workspace/project', project => project.snapshot());
register('/api/v1/dsh-workspace/file',    (project, url) => project.read(url.searchParams.get('path') ?? ''));
register('/api/v1/dsh-workspace/diff',    (project, url) => project.diff(url.searchParams.get('path') ?? ''));
register('/api/v1/dsh-workspace/logs',    (project, url) => { /* ... */ });
```

**从这段源码能读出的规格：**

1. `webServer.register({ kind, path, handler })`，`kind: 'exact'` 表示精确匹配。
2. `handler(req, res)` 拿的是**原生 Node `http` 的 req/res**——可以 `res.end(html)` 返回整页。
3. 统一错误信封：`{ status, reason, message, fields, requestId }`（社区 API 直接沿用，保证一致体感）。
4. 安全头：`Content-Type`、`Cache-Control: no-store`、`X-Content-Type-Options: nosniff`、`X-Request-Id`。
5. 本机闸门：`isLoopback(req)` 检查 `127.0.0.1` / `::1` / `::ffff:127.*`。
6. 日志：`ctx.logger.warn(error)`。

### 2.5 凭据

```js
import { credentialRef } from '@deepseek-ai/dsh-credentials'
const resolvedApiKey = config.apiKey ?? (await ctx.credentials.resolve(apiKeyRef))?.value;
```

社区插件用它保存 GitHub token：
- 写：`ctx.credentials.set(ref, token)`
- 读：`(await ctx.credentials.resolve(ref))?.value`
- **永远不要**把 token 写进配置文件、日志或返回给前端。

### 2.6 Agent 工具（形态④）

实测完整形状（`dsh-find-plugins/lib/index.js:147-202`）：

```js
export function apply (ctx) {
  ctx.tools.register(defineTool({
    name: 'find_dsh_plugins',
    description: '…给模型看的长描述，说明何时用、参数怎么填…',
    parameters: {
      query:          { type: 'string',  required: true,  description: '…' },
      limit:          { type: 'number',                   description: '…' },
      includeUnvetted:{ type: 'boolean',                  description: '…' },
    },
    output: {
      schema: { type: 'object', additionalProperties: true },
      render: (_args, value) => [{ type: 'text', text: renderText(value) }],
    },
    execute: async (args) => {
      return search({ query: String(args.query ?? ''), limit: normalizeLimit(args.limit) });
    },
    timeoutMs: 30_000,   // 仅声明式；本 harness 的工具注册表不强制截止时间
  }))
}
```

**社区插件建议注册的工具：**

| 工具名 | 作用 | 是否需登录 |
|---|---|---|
| `community_search` | 在社区帖子里搜解决方案 | 否 |
| `community_plugin` | 取某个插件的社区档案（star/issue/讨论摘要） | 否 |
| `community_post` | 发帖或回帖 | **是** |
| `community_triage` | 把一批 Issues 归类，生成「已知问题」摘要 | 否（读） |

> 注意源码注释里的一条实测事实：**`timeoutMs` 是声明式的**，本 harness 的工具注册表不强制截止时间（真正执行需要 `@deepseek-ai/dsh-tool-call-timeout-policy`）。所以社区工具必须自己做内部超时预算。

> **搜索有两条路，`community_search` 必须按登录状态分流。** 官方文档已证实**讨论本身可以被搜索**——顶层 `search` 字段支持 `type: DISCUSSION`，返回的 `SearchResultItemConnection` 上还有 `discussionCount`：
>
> ```graphql
> { search(query: "关键词 repo:moyuqing/xxx", type: DISCUSSION, first: 20) {
>     discussionCount
>     nodes { ... on Discussion { number title url } } } }
> ```
>
> 但这条路**未登录走不通**：GraphQL 未认证配额实测为 **0**；而 REST 的 `GET /search/...` 虽然未认证能用（POC-0 实测），却是**独立的配额桶**（实测：核心还剩 29 次时 search 已经 403）。所以：
> - **未登录** → `community_search` 只搜**本地缓存**（插件自己抓回来存下的帖子索引）；
> - **已登录** → 才开放 GraphQL 全站搜索。
>
> 详见 [08](08-GitHub-API-契约.md) §3.1。

## 3. client 半边规格

### 3.1 必需导出与槽位注册

实测完整形状（`dsh-workspace/lib/client/index.js:562-577`）：

```js
export const inject = ['slots', 'sessions'];

export function apply(ctx) {
    // 注入样式（用 ctx.effect 保证可回收）
    ctx.effect(() => {
        if (document.getElementById(STYLE_ID)) return;
        const style = document.createElement('style');
        style.id = STYLE_ID;
        style.textContent = STYLES;
        document.head.append(style);
        return () => style.remove();
    }, 'dsh-workspace: styles');

    // 往官方槽位挂组件
    ctx.slots.inject('sidebar.footer.action',
        () => ctx.slots.register({ name: 'sidebar.footer.action', id: 'dsh-workspace', order: 10 }, Summary));

    ctx.slots.inject('conversation.composer.dock',
        () => ctx.slots.register({ name: 'conversation.composer.dock', id: 'dsh-workspace-file-at', order: 100 }, ComposerBridge));
}
```

**这就是 client 半边的全部机制：**

```
ctx.slots.inject(slotName, () => ctx.slots.register({ name: slotName, id, order? }, Component))
```

- `inject(slotName, cb)`：声明「当这个槽位存在时执行 cb」。**槽位可能不存在**（比如手机端前端快照里没有），所以要靠 inject 而不是硬注册。
- `register(descriptor, Component)`：把 React 组件挂上去。
- `id` 必填且应全局唯一（推荐带包名前缀）。
- `order` 数字越小越靠前。

### 3.2 槽位描述符的三种形态（来自实时 Inspect 输出）

| 槽位类型 | 描述符 | 例子 |
|---|---|---|
| **list** | `{ id: string（必填）, order?: number, label?: string \| (() => string) }` | `sidebar.panellist`、`plugins.detail.section` |
| **keyed** | `{ key: string（必填） }` | `main`（key = 入口 id）、`plugins.row.config`（key = `<包名>#<行id>`） |
| **single** | 无额外参数 | `sidebar`、`settings.section` 的父级 |
| **chain** | `{ select: (owner) => unknown \| null }` | `conversation.composer` |

### 3.3 社区插件要用的槽位（精选）

完整槽位树来自 `client` 平台的 Inspect Provider 实时输出。社区用得上的：

| 槽位 | 类型 | 社区用途 | 优先级 |
|---|---|---|---|
| `main` | keyed（key = 侧栏派发的入口 id） | **社区全屏主页**。key 建议 `community` | P0 |
| `sidebar.panellist` | list | 侧栏加一个「社区」图标入口 | P0 |
| `plugins.detail.section` | list | **插件详情页下方加「社区讨论」区块** | P0 |
| `plugins.detail.badge` | list | 详情页标题旁加「讨论活跃 / 有已知坑」标签 | P1 |
| `plugins.detail.actions` | list | 详情页头部加持「去提问」按钮（在自带 switch/uninstall 之前） | P1 |
| `settings.section` | single→list | 社区设置页（client_id、owner/repo） | P1 |
| `shell.overlay` | list（`{id, order?, label?}`） | 全局发帖浮层 / 登录引导浮层 | P1 |
| `sidebar.footer.action` | list | 侧栏底部「我的帖子 / 待回复」 | P2 |
| `conversation.input.left` | list | 在对话输入框工具行左侧加「引用社区帖」 | P2 |
| `tool.call.toolview` | keyed（按 wire tool name） | 给 `community_*` 工具自定义卡片渲染 | P2 |
| `conversation.chat.turnTail` | list | 在助手回合末尾追问「这个问题社区有人问过」 | P3 |

> ⚠️ `plugins.*` 系列槽位是 DSH 官方**专门为「扩展现有插件页」留的座位**——这是把 star/issue/评论贴进插件详情页的官方通道，不是 hack。

### 3.4 client 半边的产物形态

`dsh.client` 声明后，构建产物是一个 **UMD 风格的自注册 bundle**。实测 `dsh-workspace/lib/client.js` 的首行：

```js
window.__ModuleLoader__.load({ id: "dsh-workspace", factory: (require) => {
```

**含义**：client 半边必须在浏览器全局 `window.__ModuleLoader__` 上自注册，`id` 必须与包名一致。React 通过 `require("react")` 从宿主取得，**不要打包进自己的 bundle**。

> 这就是为什么「client 插件图为空」时页面只剩 3709 字节：`__DSH_BOOT__` 的 entries 是 `[]`，没有任何 bundle 被注入，`__ModuleLoader__` 上什么都没注册。

## 4. 社区插件的完整路由表

### 4.1 形态②：独立 HTML 页面（保底通路）

| 路由 | 方法 | 返回 |
|---|---|---|
| `/community` | GET | 社区首页整页 HTML |
| `/community/plugin` | GET | 插件详情页（`?repo=owner/name`） |
| `/community/t` | GET | 帖子详情页（`?id=<discussionId>`） |
| `/community/u` | GET | 用户主页（`?login=<github login>`） |

> 这些页面**完全脱离 client 插件图**，任意浏览器/WebView 直接访问即可。样式用内联 `<style>`，交互用少量内联 `<script>` + `fetch('/api/v1/community/*')`。

### 4.2 形态③：JSON API

统一前缀 `/api/v1/community/`，统一错误信封。

| 路由 | 方法 | 说明 |
|---|---|---|
| `/api/v1/community/plugins` | GET | 插件列表（`?q=&source=&sort=&page=`） |
| `/api/v1/community/plugin` | GET | 插件档案（`?repo=`）→ 合并多源 + GitHub 元数据 |
| `/api/v1/community/discussions` | GET | 帖子列表（`?category=&q=&page=`） |
| `/api/v1/community/discussion` | GET | 帖子详情 + 评论（`?id=`） |
| `/api/v1/community/discussion` | POST | **发帖 / 回帖**（需登录） |
| `/api/v1/community/reaction` | POST | **投票 / 反应**（需登录） |
| `/api/v1/community/issues` | GET | 某插件的 Issues 聚合（`?repo=&state=`） |
| `/api/v1/community/me` | GET | 当前登录态 `{ authenticated, login, avatarUrl }` |
| `/api/v1/community/auth/start` | POST | 启动 Device Flow → `{ userCode, verificationUri, expiresIn, interval }` |
| `/api/v1/community/auth/poll` | POST | 轮询授权结果 → `{ status: 'pending'\|'ok'\|'expired' }` |
| `/api/v1/community/auth/logout` | POST | 清除凭据 |

**设计要点：**
- `auth/start` 与 `auth/poll` 分开，是因为前端要「先显示 8 位码 → 用户去授权 → 再轮询」，不能长连接阻塞。
- **token 永远不经过前端**：`poll` 成功后 token 直接落在 `ctx.credentials`，前端只收到 `{ status: 'ok', login, avatarUrl }`。
- 所有写操作 host 侧二次校验登录态。

## 5. 组装与安装

`cordis.patch.yml` 是 DSH 用来把插件插进 profile 的补丁文件。`package.json` 的 `dsh.bundle.patch` 指向它。

profile 目录里有 `cordis.yml`，但实测其内容是：

```yaml
[]   # Edit cordis.patch.yml, not this file.
```

**所以：新增插件不能改 `cordis.yml`，只能通过 bundle 声明或 `cordis.patch.yml`。**

发布的包被安装后，DSH 的 plugin-manager 会接管启用/禁用，并触发 `plugin-manager/changed` 事件。

## 8. 实测踩过的坑（写代码前必读）

| # | 坑 | 现象 | 正解 |
|---|---|---|---|
| 1 | 名字像插件但不是插件 | `dsh-webui` 没有任何 `dsh` 字段 | 判据是 `dsh.bundle`，不是名字 |
| 2 | 缺少 `./client` export | 界面完全不出现，且无报错 | `exports` 必须含 `./client` |
| 3 | 缺少 `./cordis.patch.yml` export | 安装后找不到 patch | `exports` 必须含它 |
| 4 | `files` 漏了 `lib/**/*.js` | 发布后是空包 | `files: ["lib", "cordis.patch.yml", ...]` |
| 5 | client bundle 的 `id` 与包名不一致 | 加载不上 | `__ModuleLoader__.load({ id: '<包名>' })` |
| 6 | 把 React 打进 client bundle | 体积暴涨且可能出现双 React | 用 `require("react")` 从宿主取 |
| 7 | 不声明 `inject` 直接用 `ctx.xxx` | 服务未定义 | 先 `export const inject = [...]` |
| 8 | 不用 `ctx.effect` 注册 | 插件卸载后残留 | 一律 `ctx.effect(() => ..., 'label')` |
| 9 | 以为 `timeoutMs` 会强制生效 | 请求可能无限挂 | 自己做内部超时预算 |
| 10 | 改 `cordis.yml` | 被覆盖 | 改 `cordis.patch.yml` 或 bundle 声明 |
